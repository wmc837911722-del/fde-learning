## 8. Agent / 工具调用专项（不适用则删除并说明）

不要只评最终文本。对每一步分别验证意图、权限、参数、副作用与最终状态。

| 层级 | 通过条件 | 证据 |
| --- | --- | --- |
| 工具选择 | 选择允许且最小权限的工具；不需要时不调用 | `[轨迹断言]` |
| 参数构造 | 参数完整、类型正确、来源可追溯，无越权 ID | `[schema/策略测试]` |
| 授权与确认 | 高风险动作在执行前获得正确用户/审批 | `[策略与 UI 测试]` |
| 执行语义 | 超时、重试与幂等不会产生重复副作用 | `[集成/故障注入]` |
| 业务状态 | 数据库/API 的实际提交状态符合预期 | `[状态查询]` |
| 审计记录 | 意图、授权、动作、结果可关联且已脱敏 | `[结构化日志断言]` |
| 最终响应 | 对成功、部分成功和失败的描述与真实状态一致 | `[状态-日志-响应对账]` |

高风险动作测试至少包含：重复提交、网络超时后结果未知、权限在会话中变化、工具返回恶意文本、部分步骤成功、用户撤销确认和下游不可用。
